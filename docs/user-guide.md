# cefscan 用户指南

找出电脑上所有基于 Chromium 内核的应用 —— CEF / Electron / NWJS / CefSharp / Edge /
Chrome —— 给出它们的磁盘占用与是否正在运行。

程序有两个入口，功能等价、互不依赖：

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `cefscan.exe` / `cefscan` | 控制台程序 | 纯命令行，输出 table / json / ndjson / csv / toml |
| `cefscanw.exe` / `cefscanw` | 窗口程序 | 图形界面，内嵌前端，无控制台 |

> 主平台是 Windows。Linux 上也能构建运行（遍历 + 图形界面都可用），但索引后端
> （Everything IPC）与表格里的图标列是 Windows 专属。

---

## 1. 获取与运行

从 Release 下载对应平台的压缩包，解开就是自包含目录，直接运行即可，不需要安装：

```
cefscan-{版本}-{windows|linux}-{x86_64|arm64}[-gnullvm]/
  ├─ cefscan.exe / cefscan
  ├─ cefscanw.exe / cefscanw
  ├─ README.md
  └─ LICENSE
```

Windows 有两种工具链的包：**不带后缀的是 MSVC 构建**，带 `-gnullvm` 的是 llvm-mingw 构建，
后者包里多一个 `WebView2Loader.dll`（图形界面需要，别删）。两者功能一致，挑一个即可，
不确定就用不带后缀的。每个 Release 具体出了哪些平台，看 Release 正文里的表格。

两个程序都是静态链接，只依赖 Windows 自带的系统 DLL；图形界面依赖系统自带的
WebView2（Windows 10/11 默认已装）。

## 2. 命令行 `cefscan`

### 2.1 快速上手

```bash
cefscan                                   # 扫描所有盘符，表格输出
cefscan --root "C:\Users\me"              # 只扫指定目录（可重复）
cefscan --format json -o result.json      # 结果写进文件
cefscan --kind electron --running-only    # 只看正在运行的 Electron 应用
cefscan --min-size 500MB --sort size      # 只看 500 MiB 以上的，按占用排序
cefscan --backend cefscan --threads 8     # 强制走遍历后端，指定线程数
cefscan -v                                # 附带命中的签名与最终使用的后端
```

### 2.2 参数

| 参数 | 说明 |
| --- | --- |
| `--root <DIR>` | 遍历起点，可重复；不指定则扫描所有盘符 |
| `--backend <auto\|cefscan\|index>` | 搜索后端，默认 `auto`（见第 4 节） |
| `--threads <N>` | 遍历线程数，`0` 表示自动（默认上限 8） |
| `-f, --format <table\|json\|ndjson\|csv\|toml>` | 输出格式，默认 `table` |
| `-o, --output <FILE>` | 写入文件而不是 stdout |
| `-k, --kind <KIND>` | 只列出这些类型，可重复；取值见下 |
| `--running-only` | 只显示正在运行的应用 |
| `--min-size <SIZE>` | 只显示占用不小于此值的应用，如 `512MB`、`2GiB` |
| `--sort <size\|path\|kind>` | 排序依据，默认 `size`。`kind` 按内核类型优先级 |
| `--ascending` | 升序排列。默认方向随主键：占用 / 类型降序，路径升序 |
| `--include-hidden` | 包含隐藏目录 |
| `--no-running` | 不检测运行中进程（可略微加快扫描） |
| `--exclude-dir <NAME>` | 追加排除的目录名，可重复 |
| `--exclude-path <PATH>` | 追加排除的路径，可重复 |
| `-v, --verbose` | 输出命中的签名与使用的后端 |
| `-q, --quiet` | 只输出结果，不打印汇总 |

`--kind` 的取值：`electron`、`edge`、`chrome`、`nwjs`、`cefsharp`、`mini_electron`、
`mini_blink`、`cef`、`unknown`。写错会直接报错并列出全部合法值。

`--min-size` 的单位按 1024 进制：`KB`/`MB`/`GB`/`TB`（也接受 `KiB`/`MiB`/… 写法），
不带单位就是字节数。

### 2.3 输出格式

- `table`：人类可读的表格（默认）。
- `json`：整个结果对象。
- `ndjson`：每行一个应用对象，便于流式处理。
- `csv`：逗号分隔。
- `toml`：TOML。

JSON / NDJSON / CSV / TOML 的字段名与类型定义在 [`schema.md`](schema.md)，发布后保持
向后兼容 —— 新增字段只追加且可选，不会破坏既有脚本。

### 2.4 退出码

| 码 | 含义 |
| --- | --- |
| `0` | 成功（包括一个结果都没有） |
| `1` | 扫描失败 |
| `2` | 参数或配置错误 |

## 3. 图形界面 `cefscanw`

图形界面分**三个视图**，三者**共用同一份数据**，切换视图不会重新扫描：

```
① 初始选择页  ──►  ② 经典模式（喜报 + 卡片墙）  ──►  返回
              └──►  ③ 工具模式（表格）          ──►  返回
```

### 3.1 初始选择页

两个模式选项在上，「进入」按钮在下。选择页本身不显示结果，也**没有目录输入框**
（所以第一轮扫描永远是全盘；想限定目录请进工具模式后再输入）。

「进入」只负责把你送进选中的视图，进去之后扫不扫要看情况：手上已有结果就直接复用。

### 3.2 经典模式（卡片墙）

- 整张"喜报"就是画布，没有工具条，只有左上角两个图标圆钮：**返回**和**重新扫描**。
- 正中央"喜报"二字下方是一行条数：`您的电脑里有 N 个 Chromium`。
- 结果画成卡片墙：图标 + 名称 + 占用，自动换行，每行放几张随窗口宽度自适应。
- 结果超出屏幕时**按整行**平滑向下滚动，并且会**自动跟随最新一行**；你往上滚就停下，
  滚回底部会自动恢复跟随。
- 点击卡片会在资源管理器中定位到该应用。

经典模式的结果一**张张浮现**（有节奏地出现，而不是一次性铺满），所以结果很多时
请耐心等它出完。

### 3.3 工具模式（表格）

- 顶部工具栏：返回、品牌名、**目录输入框**、后端状态、开始扫描、状态行。
- 下方是汇总栏（应用数 / 总占用）和表格：图标 + 名称 + 类型 + 占用 + 运行状态 + 路径。
- 点表头可以排序（按占用 / 路径 / 类型）；**排序只影响表格**，切回经典模式时卡片的
  相对位置不会被打乱。
- 点整行展开完整路径，并在资源管理器中定位。
- 路径列默认折叠成「根 + 3 层目录 + … + 文件名」，保证尾部一定是完整的文件名：

  ```
  C:\Users\16695\AppData\Local\Programs\WorkBuddy\WorkBuddy.exe
    → C:\Users\16695\AppData\…\WorkBuddy.exe
  ```

  点整行即可看到完整路径。

### 3.4 后端状态

工具栏上有一个显示当前搜索后端的标签，形如 `自动（cefscan）` 或 `自动（Everything）`。
它在你**进入工具模式时**、以及**点它时**刷新，也就是在你按下"开始扫描"**之前**就能看到
这次会由谁去找。探测不到时会显示 `自动（未确定）`。

## 4. 搜索后端

| 后端 | 平台 | 依赖 | 说明 |
| --- | --- | --- | --- |
| `auto` | — | — | 先试索引，失败回落遍历（默认，也是图形界面唯一会用的） |
| `cefscan` | 全平台 | 无 | 自写的并行文件系统遍历 |
| `index` | Windows | Everything（**非精简版**） | 走 IPC 查索引，毫秒级 |

- **`auto`**：有可用的索引服务就用索引，否则自动回落到遍历。回落是**静默且必然成功**
  的 —— IPC 失败绝不会让整次扫描失败。
- **`cefscan`**：强制走自写遍历。不依赖任何外部服务。
- **`index`**：强制走索引。没有可用索引服务时会**报错**（而不是回落）。

Everything 的**精简版（Lite）没有 IPC 接口**，装了也用不了索引后端，程序会自动回落。
索引是全局的，所以 `--root` 与排除规则会在**结果侧**再筛一遍，不会因为走索引而漏掉限制。

图形界面不提供后端选择项，只有"自动"。理由：有索引服务时用索引严格优于遍历（毫秒对
秒级，结果逐条一致），没有时想选也选不上，用户没有决策所需的上下文。

## 5. 结果是怎么算出来的

- **应用名**：从结果路径往上找第一个"有意义"的目录名，跳过版本号目录
  （`154.0.4258.37`、`app-3.6.6`、`Workstation-17.0.0`）和通用目录名
  （`Application`、`Bin64`、`runtime`、`64bit`、`bin32` …），以及 `<前缀>_Data`
  这类通用后缀目录（`BH3_Data`、`App_Data`、`Cache_Data` …）。撞到用户 / 系统目录
  （`Programs`、`LocalAppData`、`steamapps` …）就退回文件名。
- **磁盘占用**：该应用所在目录树的总体积。
- **是否运行**：枚举系统进程并与应用路径比对（路径会做归一化，`\\?\` 前缀、UNC、
  大小写都处理过）。
- **默认排除**：`node_modules`、`target`、回收站、`System Volume Information`，
  以及 Windows 的 `WinSxS` / `servicing` / `Recovery`。用 `--exclude-dir` /
  `--exclude-path` 追加更多。

## 6. 常见问题

**Q：扫描很慢怎么办？**
先确认是不是走了遍历后端（`-v` 会打印实际后端，图形界面看工具栏标签）。有 Everything
时索引是毫秒级。也可以用 `--root` 缩小范围，或调 `--threads`（8 左右通常是甜点，
再高收益有限）。

**Q：装了 Everything 但显示的是 `cefscan`。**
多半是精简版（Lite），它没有 IPC 接口。装完整版即可。也可能 Everything 没在运行。

**Q：`--backend index` 报错了。**
`index` 是"强制用索引"，没有可用索引服务时就会报错。想自动回落请用 `auto`。

**Q：`cefscan --root C:\` 或 `--root /tmp/foo` 扫不出东西。**
已修复。被排除的平台目录若落在你显式指定的 root 之内，就不再排除。

**Q：应用名看起来不像应用名。**
名称是纯字符串启发式（不读文件内容），遇到不认识的目录布局可能退化成文件名。
这属于可改进项。

**Q：图形界面第一轮为什么总是全盘？**
选择页没有目录输入框（有意为之）。进工具模式后可以在输入框里填目录再扫。
